# reSwitch reliability and usability review — 26 October 2026

This review covers the mobile and desktop launchers, shared library/import code,
Chat service and native bridge, save archive/restore code, the guest-token Worker,
native host/graphics checks, and preparation/installation tools. It preserves the
existing game assets, identities, credentials, bundle IDs, libraries, and saves.
It does not certify every supported game or claim a measured gameplay speedup.

## Changes

- iPhone/iPad HOME now supports vertical controller navigation to the dock,
  held-direction repeat, stick hysteresis, and a visible dock selection. Input
  handlers stop acting when the app is backgrounded. Portrait cards and bottom
  navigation retain their established sizes and positions.
- Touch footer controls meet the 44-point target size. Compact landscape reserves
  space for them; light-mode navigation retains each icon's original color with
  stronger contrast. Profile controls accommodate larger text.
- Mac keyboard arrows, Return, and Escape follow the same dock focus rules as a
  controller. Polling pauses outside the foreground. Shorter desktop windows use
  tighter spacing and smaller covers; Reduce Motion disables selection scrolling
  animation. Empty library searches offer a clear reset action.
- Mac library load/recovery, path checks, cover decoding, imports, writes, launch
  directory preparation, and profile-photo processing leave the main actor.
  Writes are serialized by the model's operation state, and canceled availability
  scans cannot overwrite newer results. Selecting a card clears menu focus.
- Mac artwork is decoded only for visible cards/rows, with a 24 MiB / 32-cover
  least-recently-used cache and serialized background decoding. Hidden HOME does
  not compete with library scrolling; returning HOME reloads evicted images.
- Mac library writes enforce the same 32 MB limit as reads before touching either
  saved copy. IDs normalize before duplicate detection. A missing primary can
  recover from its backup, and invalid existing data is retained for recovery.
- Portable library export processes one cover at a time and stops at 32 MB before
  loading further images. File reads reject special files and honor cancellation.
- Phone file imports journal the gap between copying a file and updating the
  index. Completed interrupted imports recover on reopening. Missing or truncated
  imported copies display an availability warning instead of a green stored state.
  Deletion recovery also runs before mutations after relaunch, restores indexed
  copies, and cleans completed removals only with valid index/filename evidence.
  Conflicts, special files, and missing/corrupt indexes are preserved.
- Save checkpoint creation avoids one full hashing pass. Enumeration rejects
  unreadable subfolders instead of making incomplete backups. Restore extracts
  into the final recovery location and swaps it with the active save; the previous
  version is retained. Changed selected records and malformed local history are
  rejected without replacing progress.
- Chat invalidates stale microphone approvals after leaving/rejoining, protects
  audio-device requests across account sessions, retains local participant controls
  during gateway reconnection, refreshes missed messages on recovery, and shows an
  explicit offline state with Reconnect.
- Mac installation verifies a staged app before replacement and rolls back a
  failed swap on the destination filesystem. A previous app is retained even when
  the archive directory is unavailable; unrelated app bundles are not replaced.
  The Mac bundle now takes its version/build from Xcode settings, preventing a
  release package from retaining the previous version's hardcoded metadata.
- Graphics fixtures now use the current program, texture-storage, upload-ordering,
  and opt-in optimization APIs. Exact pixel and negative assertions remain. The new
  `run-self-contained` target separates synthetic validation from checks requiring
  extracted shader-reflection fixtures. No runtime or shader-chain change was
  required to resolve those fixture failures.

## Delivery and remaining acceptance

- iPhone/iPad: build 19, `reSwitch-iPhone-iPad-build19-signed.ipa`.
- Mac: version 1.2.1 build 6, `reSwitch-macOS-1.2.1-build6-signed.zip`.

Both are under `launcher/build/review-2026-10-26/`, alongside the original unsigned
packages. At the owner's subsequent request, both release builds were rebuilt and
signed. The mobile package uses Apple Development and a valid profile covering
the owner's iPhone and iPad; its iCloud container and key-value entitlements were
verified. The Mac package uses Developer ID Application with hardened runtime and
a secure timestamp; it has not been notarized. Each packaged archive passed CRC
checks and strict nested code-signature verification after extraction. Package
hashes are in `artifacts.json`; signing checks are in
`validation/signed-packages.json`.

At the owner's subsequent installation request, the signed release replaced the
launchers in place on the iPhone, iPad, and Mac. Both mobile inventories report
build 19; the installed Mac reports 1.2.1 build 6 and passes strict signature
verification. CoreDevice launch checks passed on both mobile devices, with their
processes present on follow-up. The iPad HOME was visually inspected after unlock.
The iPhone locked before its screenshot, so its physical UI was not re-inspected.
Mac HOME, Settings, and the existing connected guest Chat session were inspected.

Before/after checks preserved all 11 iPhone library/artwork/profile/import files,
all 4 iPad library/artwork files, and all 3 Mac application-support files by hash.
All existing preference values were retained: 5 on iPhone, 2 on iPad, and 7 on
Mac. Backups and the previous Mac app are retained under
`~/Documents/iSwitch Backups/2026-10-26/build19-build6-install/`; delivery records
are in `validation/iphone-installation.json`, `ipad-installation.json`, and
`mac-installation.json` beside the packages. The iPad's first install attempt
timed out over the local network; the retry installed successfully without
uninstalling the existing app.

No separate game app, game save, credential, or cloud deployment was replaced.
The source is committed and pushed to the owner's GitHub fork on
`codex/iswitch-launcher`; signed packages, credentials, vendor SDK binaries, and
game material remain outside version control.

Physical controller feel, two-person voice/audio routing, and extended gameplay
remain device acceptance checks. Save-library changes must also be included when
native game apps are next rebuilt; changing the launcher does not replace code
already installed inside separate game apps. Mac iCloud save sync remains outside
the existing implementation. A filesystem copy can stop at its boundaries, not
in the middle of `FileManager.copyItem`. Save replacement and history persistence
are separate commits; both save versions survive a later history-write failure,
but the next launch may require a conflict choice.
