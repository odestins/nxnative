## Additional local robustness fixes

- **Save concurrency:** per-transaction reader/writer locks keep failed writes and commit recovery ordered for the same backing save. File-handle transaction ownership is atomic, and test failure-injection initialization is thread-safe. Tests cover alias mounts, independent saves, failures, recovery and concurrent write/commit behavior while preserving the existing local save hooks.
- **Controller lifecycle:** disconnecting or suspending a controller clears its held state and unread press edges. Reconnecting into a player slot cannot replay the old controller's pending press. Ordinary short presses still remain latched until the game reads them. iOS slot ownership and callbacks are confined to the main queue.
- **Library recovery:** only a readable, valid current library can replace the last known-good backup. Recovery writes the same bounded bytes it validated, rather than rereading a potentially different backup. A corrupted primary encountered after initial load no longer overwrites the recovery copy on the next save.
- **Library size:** enforce the existing 32 MB read budget before publishing a library, including UTF-8 metadata and final JSON size. A small grapheme count can contain a large number of combining characters; oversized edits now leave both the in-memory library and on-disk primary/backup intact.
- **Cloud metadata cancellation:** retain and cancel the actual detached scan worker. Superseded scans check cancellation between file reads and cannot publish a partial or stale list. Cancellation does not forcibly interrupt a filesystem coordination call already in progress; it prevents the remaining work and stale publication.
- **Package scanning:** validate PFS0 directory counts and byte extents before allocation, capped at 65,536 entries and 16 MiB of directory data. Validate names and payload bounds, skip directories named like packages, accept uppercase extensions, and continue past malformed package candidates. Truncated NPDM metadata gets a readable extraction error.

These changes do not redesign platform interfaces or copy a desktop layout onto the phone/tablet. Library and cloud changes improve the existing shared persistence behavior.

### Measured CPU texture-conversion improvement

On this Mac's M4 Max, the updated CPU deswizzle routine was **4.36–5.73 times faster** across seven warmed synthetic cases (RGBA8 even/odd dimensions, padded rows, BC1/BC3 block data and 3D). RGBA8 1920×1080 dropped from a median **1,045.13 µs to 218.78 µs** per call. Both implementations used identical host `-O1` flags, one unchanged texture-layout object and deterministic inputs. Eight warmups preceded eleven alternating samples per implementation; all 154 samples matched byte-for-byte and by checksum, including padding.

This measures the CPU conversion routine on the Mac, not game FPS, first-load time or iPhone/iPad performance. The harness, raw CSV, source hashes and complete report are retained in `launcher/build/review-2026-10-28/evidence/deswizzle-bench/`.

- **MetalFX and broad rendering/presentation redesigns:** defer until their dependencies, device support, resource costs and gameplay behavior can be tested together.
- **New/updated game profiles and wholesale profile synchronization:** upstream playability claims do not establish compatibility for the owner's installed game versions. No profile addresses or fixes were copied onto unverified builds, and no new game was declared playable.

No game packages, keys, firmware, extracted assets or saves were added to the repository. There was no full game preparation or shader regeneration pass.
